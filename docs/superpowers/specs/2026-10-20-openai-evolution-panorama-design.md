# OpenAI 产品与模型演进全景设计

## 1. 目标

构建一个中文、单文件、可交互且可持续自动更新的 OpenAI 产品与模型演进网页。网页从 2015 年 OpenAI 成立与早期产品基础开始，覆盖 GPT、o 系列、ChatGPT、API Platform、Codex、图像、语音、视频、订阅计划、安全发布与模型迁移，首次数据截止 2026-10-20，之后由 GitHub Actions 每日推进。

最终交付包括：

- 单文件纯前端网页 `outputs/openai-chatgpt-evolution-panorama.html`；
- 结构化历史数据与来源索引；
- 无第三方运行时依赖的 Python 构建器与更新器；
- 自动测试、自动提交和 GitHub Pages 发布工作流；
- 公开仓库 `yyst73Serendipity/openai-evolution-panorama`；
- 在线地址 `https://yyst73serendipity.github.io/openai-evolution-panorama/`。

## 2. 范围与边界

### 2.1 时间范围

- 起点：2015-12 OpenAI 成立。
- 初始截止：2026-10-20（Asia/Shanghai）。
- 后续截止：每次成功收录官方新事件后推进到最新事件日期。
- 早期研究只收录直接奠定后续模型或产品路线的节点，不做完整论文史。

### 2.2 收录主线

1. **模型**：GPT-1、GPT-2、GPT-3、InstructGPT、GPT-3.5、GPT-4、GPT-4 Turbo、GPT-4o、o 系列、GPT-5/5.x、GPT-6 系列及 mini、nano、pro 等分层。
2. **ChatGPT**：Research Preview、联网、插件、文件与数据分析、视觉、语音、记忆、GPTs、Projects、Tasks、Canvas、Search、Deep Research、Images、Study Mode、Agent 等。
3. **API / Agents**：API、Chat Completions、Assistants、Responses、Realtime、Batch、Structured Outputs、工具调用、Agents SDK、Web Search、File Search、Computer Use 等。
4. **Codex**：Codex 模型、CLI、云端编码代理、桌面入口、代码审查、订阅可用性与模型迁移。
5. **多模态**：DALL·E、Whisper、Voice、GPT Image、ChatGPT Images、Sora 和视频能力。
6. **订阅**：Free、Plus、Pro、Go、Business/Team、Enterprise、Edu 与 API 价格快照及重要调价。
7. **迁移与退役**：ChatGPT 与 API 的模型差异、Preview 迁移、模型弃用、Assistants 等平台迁移。
8. **安全与治理**：仅收录直接改变模型发布方式、功能权限或产品使用边界的安全节点，包括 GPT-2 分阶段发布、RLHF/InstructGPT、System Card、Preparedness Framework、Model Spec 等。

### 2.3 不收录内容

- 一般融资、估值、董事会、人事与诉讼新闻；
- 与产品能力或可用性无直接关系的公司活动；
- 无法追溯到官方原始来源的传闻；
- 仅由第三方媒体披露、尚未被 OpenAI 官方确认的信息；
- 社交媒体重复转发或营销文案。

## 3. 资料来源与证据等级

来源优先级：

1. `openai.com` 官方发布、研究与产品文章；
2. OpenAI 统一 Release Notes；
3. OpenAI Help Center 的 ChatGPT 与 Model Release Notes；
4. `developers.openai.com` 与 `platform.openai.com` 文档、Changelog、模型与定价页；
5. `learn.chatgpt.com` 的 ChatGPT Work/Business/Enterprise 官方资料；
6. OpenAI、ChatGPT、OpenAI Developers 官方 X 账号，仅用于官网缺失历史日期时补充。

每条事件必须包含：日期、日期精度、类别、产品线、模型家族、标题、摘要、相对变化、优化重点、适用范围、战略意义、来源标签、官方 URL、收录方式和核验状态。

证据状态：

- **人工整理**：根据官方原文人工归纳，可写明前代差异与战略意义；
- **自动收录**：更新器根据官方标题和摘要生成，只用保守措辞，不推断未明确公布的指标；
- **页面变更**：价格、发布说明或弃用页正文发生变化，提示读者核对官方原文。

X 页面不得作为自动更新的主发现源。其接口、登录和页面结构不稳定，自动系统以官网 sitemap、Release Notes 和文档页为主。

## 4. 数据结构

`work/timeline-data.json` 顶层字段：

```json
{
  "cutoff": "2026-10-20",
  "lastChecked": "",
  "events": []
}
```

事件字段：

```json
{
  "date": "2022-11-30",
  "precision": "day",
  "category": "ChatGPT",
  "track": "ChatGPT 产品",
  "family": "GPT-3.5",
  "title": "ChatGPT Research Preview",
  "summary": "发布了什么",
  "delta": "相对前一阶段改变了什么",
  "optimization": "优化重点",
  "availability": "适用用户、计划、地区与平台",
  "significance": "为什么重要",
  "sourceLabel": "OpenAI",
  "sourceUrl": "https://openai.com/...",
  "autoGenerated": false,
  "verification": "人工整理"
}
```

`track` 用于产品轨道筛选，`family` 用于模型家族筛选；非模型事件允许 `family` 为空字符串。时间线按日期升序保存，同日按类别与标题稳定排序。

## 5. 页面信息架构

1. **Hero**：范围、截止日期、最后自动检查时间、事件数、官方来源数。
2. **全景概览**：年度事件分布、八条产品轨道和五个发展阶段。
3. **可交互时间线**：搜索、年份、类别、产品线、模型家族、排序、快捷筛选、只看最近新增、展开/收起和重置。
4. **模型谱系**：GPT、o 系列及各档位定位变化；明确 ChatGPT 产品名与底层模型名的区别。
5. **ChatGPT 功能矩阵**：对话、搜索、研究、创作、记忆、协作、代理的能力演进。
6. **API 与 Agents**：从文本补全到 Responses/Agents 平台，展示接口范式与工具层变化。
7. **Codex 专题**：从模型到编码代理、CLI、云端与代码质量治理。
8. **多模态谱系**：图像、语音和视频产品与底层模型演进。
9. **订阅计划**：历史计划节点与当前美国公开价格快照，区分 ChatGPT 订阅和 API 用量计费。
10. **API 模型与价格**：当前标准输入/输出或媒体计费快照，注明缓存、Batch、Fast、区域和第三方云差异。
11. **迁移与退役**：重要弃用节点、ChatGPT/API 可用性差异及持续迁移流程。
12. **战略转折**：从预训练到指令对齐、多模态、推理、代理和工作平台的关键变化。
13. **方法与不确定性**：证据口径、自动收录规则、日期精度和价格提醒。
14. **官方来源索引**：去重后的原始官方链接。

## 6. 视觉与交互设计

- 视觉不复制 Claude 网页，采用 OpenAI 产品线适合的中性黑白、冷灰与高饱和轨道色；保持克制和高对比。
- 主时间线以产品轨道颜色和文字标签双重编码，不能只靠颜色表达类别。
- 所有功能在 320px 宽度可用；复杂表格可横向滚动或转卡片。
- 原生语义控件，支持键盘操作、焦点样式、跳过链接、`aria-live` 和 `noscript` 说明。
- 尊重 `prefers-reduced-motion`，提供打印样式和深浅主题。
- URL hash 保存筛选状态；新窗口外链必须使用 `rel="noopener noreferrer"`。
- 不使用 CDN、外部字体、外部 CSS、外部 JavaScript、XHR 或运行时数据请求；下载后的 HTML 可离线完整查阅。

## 7. 构建架构

采用 Python 3 标准库，不新增第三方依赖：

- `work/timeline-data.json`：人工整理与自动收录的结构化事件。
- `work/build-page.py`：字段、日期、官方域名和排序校验；生成完整单文件 HTML。
- `work/source-config.json`：发现源、受监控页面、官方域名和关键词。
- `work/source-state.json`：已知 URL、页面摘要和最后检查时间。
- `work/update-openai-panorama.py`：抓取 sitemap/页面元数据、检测受监控页面变化、分类、去重并原子写入。
- `outputs/openai-chatgpt-evolution-panorama.html`：唯一用户交付网页。

构建器只接受 `https` 且主机位于官方允许清单的来源。数据写入使用同目录临时文件和 `os.replace`，防止中断破坏 JSON。

## 8. 自动更新与发布

GitHub Actions 工作流：

- 每天北京时间 08:15（UTC 00:15）执行；
- 支持 `workflow_dispatch` 手动运行；
- 检出仓库并配置 Python 3.12；
- 运行更新器、构建器、完整测试和 JavaScript 语法检查；
- 有变化时以机器人身份提交指定文件；
- 复制单文件为 Pages 的 `index.html` 和原文件名；
- 使用 GitHub Pages 官方 Actions 发布；
- 任一步骤失败均保留上一版线上页面，不提交半成品。

更新规则：

- 新发现文章必须来自官方域名、具有可靠日期、晚于当前截止且不晚于检查日；
- 规范化 URL 后去重，移除 query、fragment 与尾部斜杠差异；
- 同次异常新增超过 20 条时终止发布，避免 sitemap 或选择器变化造成污染；
- 受监控页首次执行只建立基线，之后正文摘要变化才生成事件；
- 单一受监控 URL 在同一日期最多生成一条页面变更事件；
- 自动事件明确显示“自动收录”，不自动重写人工事件；
- `CHANGELOG.md` 记录每次新增的日期、类别、标题和来源。

## 9. 错误处理与安全

- 网络请求限制为官方 HTTPS 域名，设置明确 User-Agent、响应大小上限、超时和有限重试；
- 不使用 CORS Proxy、抓取代理或第三方内容转换服务；
- 不在网页、日志或仓库中保存 API Key；
- 页面生成使用 HTML 转义，时间线前端以 DOM API 创建节点，避免把外部元数据直接拼接为可执行 HTML；
- sitemap 或页面解析失败时输出中文诊断并让工作流失败，不静默删除历史数据；
- 构建前验证事件字段、顺序、截止日期、来源主机和条目数量下限；
- 自动新增异常、事件日期倒退或空时间线均阻止发布。

## 10. 测试策略

使用 `unittest` 和标准库 HTML/XML 解析器，至少覆盖：

- sitemap 命名空间、JSON-LD 日期和页面元数据解析；
- 官方域名允许清单、非官方 URL 拒绝、URL 规范化与去重；
- 事件分类、产品线/家族映射和自动收录保守措辞；
- 当前日期、未来日期、日期精度和动态截止边界；
- 异常新增数量保护、原子写入和页面摘要变更；
- 历史事件规模、代表性模型/产品/订阅/迁移节点；
- 必要章节、筛选控件、深浅主题、移动端和无障碍基础；
- 所有外链 HTTPS、安全新窗口属性和官方域名；
- 无外部 CSS、JS、字体、CDN 和运行时网络依赖；
- GitHub Actions 的计划时间、权限、测试、提交和 Pages 发布步骤；
- 生成网页内嵌 JavaScript 通过 `node --check`。

## 11. 文档与版本控制

- `README.md` 说明功能、目录、构建、测试、自动更新、Pages 配置和数据口径；
- `CHANGELOG.md` 保存初始版本与自动收录日志；
- 项目采用独立 Git 仓库和 `main` 分支；
- 自动提交只包含时间线、状态、网页与更新日志；
- 不修改或覆盖用户其他仓库；
- 首次上线前核验 GitHub Actions 成功、Pages HTTP 200、页面关键标记和本地/远程同步状态。

## 12. 验收标准

- 首版时间线覆盖 2015-12 至 2026-10-20，核心产品与模型主线无明显断层；
- 每条人工事件都有可打开的官方来源及“相对变化”字段；
- 页面可在无网络环境中完整使用搜索、筛选、展开和主题功能；
- 构建与全部测试通过，网页无未替换占位符，内嵌脚本语法通过；
- 公开仓库与 GitHub Pages 创建成功；
- 手动触发一次更新工作流后，检查、测试、提交和 Pages 发布均成功；
- 在线网页返回 HTTP 200，显示正确事件数、截止日期与最后检查时间。
