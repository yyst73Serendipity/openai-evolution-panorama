# OpenAI 演进全景 UI 改版设计说明

## 1. 背景与目标

当前页面已经具备完整的数据、筛选、专题视图、深浅主题、打印和自动发布能力，但视觉表达偏向通用 SaaS Dashboard，难以体现“官方资料驱动的技术历史档案”这一核心定位。时间线事件数量较多，年份锚点、重点事件和专题章节之间的视觉层级也不够明显。

本次改版采用“数字档案馆 / 技术年鉴”方向，在不改变历史事实数据和自动更新边界的前提下，重构信息层级、长页导航、时间线、筛选工具和专题表达，使页面更适合快速扫描、定向检索和连续阅读。

## 2. 成功标准

- 首屏能在短时间内说明页面主题、资料范围、更新状态和主要入口。
- 桌面端可以随时定位主要章节，并明确感知当前章节和阅读进度。
- 时间线以年份为主要视觉锚点，关键节点与普通更新有明确层级。
- 搜索和组合筛选的当前状态、结果数量与清除方式直观可见。
- 模型、ChatGPT、API、Codex、多模态和订阅等专题不再全部使用同一种卡片表达。
- 页面继续保持单文件、纯前端、离线可用，不新增第三方依赖和运行时网络请求。
- 保留深浅主题、URL hash、键盘操作、响应式、打印和减少动态效果偏好。
- 自动更新产生的新事件无需人工修改模板即可进入正确年份、轨道和自动收录样式。

## 3. 非目标

- 不修改 `work/timeline-data.json` 中的历史事实、来源或事件结论。
- 不改变自动发现、数据写入、GitHub Actions 发布和来源校验逻辑。
- 不引入图表框架、CSS 框架、外部字体、CDN 或图片素材。
- 不将当前单文件页面改造成多页面应用或前端框架项目。
- 不增加依赖外部接口才能工作的交互能力。

## 4. 视觉方向

### 4.1 设计语言

页面采用编辑式技术年鉴布局：大号年份、细分割线、紧凑元数据、明确栅格和克制的轨道色。视觉重点来自排版和信息结构，而不是大面积渐变、厚阴影或高饱和背景。

建议基础色：

- 浅色背景：`#f4f3ef`
- 浅色内容面：`#fbfaf7`
- 深色背景：`#111210`
- 深色内容面：`#191b18`
- 主要文字：`#111318`
- 次要文字：`#676a70`
- 品牌强调色：`#0d8f70`
- 浅色边框：`#cfd0ca`

八条轨道继续拥有可区分的颜色，但颜色只用于节点、细线、短标签和局部状态，不作为整张卡片的大面积背景。

### 4.2 排版

继续使用系统字体栈，不加载外部字体。中文标题减少过度粗黑，正文保持适合长文本阅读的字号与行高；年份、日期、统计数字和英文标签使用更紧凑的字距与等宽数字特性，形成档案编号感。

### 4.3 圆角、阴影与动效

- 中小圆角，避免所有内容都成为大圆角气泡。
- 主要依靠边框、留白和层级分隔，不使用厚重阴影。
- 动效只用于导航状态、筛选反馈、内容展开和返回顶部。
- 在 `prefers-reduced-motion: reduce` 下取消非必要过渡和滚动动画。

## 5. 页面结构

### 5.1 顶部栏

顶部栏保留品牌标识和主题切换，同时增加紧凑的页面状态入口。桌面端顶部栏与章节导航协作，移动端只保留必要操作，避免占据过多垂直空间。

### 5.2 首屏

首屏改为非对称编辑式布局：

- 左侧包含官方资料驱动标签、主标题、简介和两个页面内入口。
- 右侧以大号 `2015—当前年份` 作为视觉核心，并紧凑展示事件数量、轨道数量和来源数量。
- 首屏下方使用独立状态栏展示资料核验截止日、最后检查时间、最新确认事件和自动更新状态。
- 删除当前四张 Dashboard 指标卡，避免统计信息重复占据空间。

首屏入口只执行页内定位，不增加新的业务状态：

- “进入时间线”定位到时间线章节。
- “查看最新更新”定位到最新年份或当前排序下的第一组事件。

### 5.3 全局章节导航

桌面端增加 sticky 章节目录，包含总览、时间线、模型、ChatGPT、API / Agents、Codex、多模态、产品与计费、迁移和来源。目录需要：

- 点击后定位对应章节。
- 根据当前可见章节更新活动状态。
- 展示页面阅读进度。
- 提供返回顶部操作。

移动端使用横向滚动章节条或折叠菜单。目录只增强导航，不改变现有章节 `id` 和外部链接能力。

### 5.4 时间线筛选工具

筛选区改为 sticky 研究工具条：

- 搜索框为主要控件。
- 年份、轨道、产品线、模型家族、排序和最近 30 天保持现有功能。
- 当前生效条件显示为可单独移除的筛选标签。
- 显著显示“当前结果数 / 总事件数”。
- 提供清除全部筛选的明确入口。

筛选标签是现有筛选状态的另一种操作入口，不建立第二份状态。所有控件、标签、事件显示和 URL hash 均由同一份筛选状态驱动。

### 5.5 年份分组时间线

时间线从连续事件列表改为年份分组：

- 每个年份有大号年份标题、该年事件数量和分隔线。
- 年份组按现有时间排序方向排列。
- 筛选后没有可见事件的年份组整体隐藏。
- 自动更新新增事件根据日期自动进入对应年份，不需要修改模板。

事件视觉分为两级：

- 关键节点：更宽松的版式、更醒目的标题和里程碑标识。
- 普通更新：紧凑版式，保留日期、轨道、标题和摘要。

若现有数据没有稳定的关键节点字段，则使用已有重要性或类型信息；不得通过标题关键词进行不可解释的推断。无法稳定判定时，首轮改版只做统一事件卡和自动收录样式，不新增虚假的重要级别。

事件展开后继续显示相对变化、优化重点、可用范围、战略意义和官方来源。自动收录与页面变更事件使用独立标签和边框样式，与人工整理内容区分。

### 5.6 专题章节

专题章节使用统一视觉语言，但采用不同信息结构：

- 模型：代际阶梯与谱系关系。
- ChatGPT：能力层级和产品形态演进。
- API / Agents：接口范式与开发平台演进。
- Codex：研究模型、工具、代理与产品形态阶梯。
- 多模态：文本、图像、语音和视频媒介矩阵。
- 产品与计费：计划和能力对照矩阵。
- 模型迁移：旧模型到推荐替代模型的迁移路径。
- 来源索引：按年份或来源类型组织的档案入口。

首轮实现优先改变布局和层级，不修改专题内容结论。移动端的宽表格应使用明确横向滚动容器或转换为堆叠卡片，避免页面整体横向溢出。

## 6. 组件边界

页面仍由 `work/build-page.py` 生成，但模板内部按职责划分清晰区域：

- 页面框架：顶部栏、首屏、章节导航、页脚。
- 时间线工具：筛选控件、筛选标签、结果计数。
- 时间线视图：年份组、事件卡和展开内容。
- 专题视图：各专题的静态结构与数据渲染。
- 全局交互：主题、章节观察、阅读进度、返回顶部和键盘操作。

JavaScript 状态保持单向：从控件或 URL hash 读取筛选状态，统一计算可见事件，再更新事件、年份组、筛选标签、计数和 URL。章节导航状态不参与筛选数据流，避免两类状态互相耦合。

## 7. 响应式与无障碍

### 7.1 桌面端

- 使用编辑式双栏首屏。
- 章节目录常驻。
- 时间线年份与事件内容形成明确的主次列。

### 7.2 平板端

- 首屏压缩为较窄双栏或上下布局。
- 章节目录可改为顶部横向滚动。
- 筛选器允许分行，但搜索和结果数保持优先。

### 7.3 移动端

- 首屏单列展示。
- 大号年份根据视口缩放，避免截断。
- 筛选控件使用单列或双列紧凑布局。
- 时间线去除非必要装饰列，事件卡占据主要宽度。
- 表格不得导致页面整体横向滚动。

### 7.4 无障碍

- 保留语义化标题层级和 landmark。
- 导航活动状态使用 `aria-current`。
- 筛选标签删除按钮提供明确的可访问名称。
- 展开按钮继续使用 `aria-expanded` 和正确关联。
- 颜色不作为唯一状态表达方式。
- 焦点样式必须清晰可见。
- 深浅主题均满足基本文本对比度要求。

## 8. 数据流与自动更新兼容性

构建过程仍以 `work/timeline-data.json` 为单一事实源：

1. Python 构建器读取并校验时间线数据。
2. 构建器生成首屏统计、专题结构、年份分组和事件 HTML。
3. 数据与脚本继续内嵌到最终 HTML。
4. 浏览器从内嵌数据初始化筛选状态。
5. 用户操作更新统一筛选状态。
6. 页面同步更新事件可见性、年份组、结果数、筛选标签和 URL hash。

自动更新脚本只需继续更新数据并运行构建器；新的年份和事件会自然进入页面，不增加额外维护步骤。

## 9. 错误与边界处理

- 事件日期缺失或格式非法继续由构建阶段校验阻止，不在前端静默修补。
- URL hash 含未知筛选值时忽略无效值，并使用可用状态渲染页面。
- 筛选结果为零时显示明确空状态，并保留清除筛选入口。
- IntersectionObserver 不可用时，章节链接仍可点击；只退化当前章节高亮和进度增强，不影响内容访问。
- JavaScript 失效时，页面仍应展示完整静态内容和官方来源；筛选与展开属于渐进增强。
- 打印模式展开必要内容，隐藏交互控件、sticky 导航和纯装饰元素。

## 10. 测试策略

### 10.1 构建与结构测试

在 `tests/test-openai-evolution-panorama.py` 中验证：

- 新首屏、状态栏、章节导航、阅读进度和筛选标签容器存在。
- 时间线按年份分组，并保留所有事件。
- 年份组包含事件数量和稳定标识。
- 筛选、主题、打印、无障碍和 URL hash 相关结构仍存在。
- 不出现 CDN、外部字体、外部脚本或运行时数据请求。
- 输出仍为单文件 HTML。

### 10.2 交互与脚本测试

验证或静态检查：

- 筛选状态统一驱动事件、年份组、标签和结果数。
- 单独移除筛选标签和清除全部筛选不会产生第二套状态。
- 零结果状态可恢复。
- 章节导航具有活动状态更新和降级路径。
- 内嵌 JavaScript 通过 `node --check`。

### 10.3 回归测试

继续运行：

- 时间线数据契约测试。
- 自动更新测试。
- GitHub Actions 静态边界测试。
- 构建后 HTML 测试。

### 10.4 视觉验收

浏览器人工检查以下场景：

- 1440px 桌面端。
- 768px 平板端。
- 390px 移动端。
- 浅色和深色主题。
- 搜索、组合筛选、筛选标签、清空和零结果。
- 年份正序与倒序。
- 事件展开与键盘焦点。
- 长标题、长来源列表和自动收录事件。
- 打印预览与减少动态效果。
